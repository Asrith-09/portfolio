ETABS Foundation Auto Tool

PythonETABS APIIS 456
Problem
Foundation sizing is a spreadsheet loop: pull reactions, size against bearing capacity, check shear, group repeats, then model every footing by hand.
Solution
Reads column reactions and the selected load combinations, sizes isolated footings against safe bearing capacity, groups them within a set tolerance, and builds the footing geometry back into ETABS.
Impact
Resolved 40 columns into 15 footing groups on the demonstration model, cross-checked against manual calculations.
How it works

Reactions are pulled per column for each selected combination, and the governing case drives the sizing. Footings are sized against the entered safe bearing capacity, then checked for punching shear and one-way shear before a size is accepted.

Grouping runs on a tolerance the engineer sets. Footings within that band collapse into a single type, which is what keeps a schedule buildable rather than forty bespoke sizes. Geometry is then written back through the ETABS API rather than modelled by hand.

ETABS Property Validator

PythonETABS APIExcel
Problem
Section names drift from geometry as models are edited. A frame called C 900×600 that is actually 600×900 analyses fine and fails review late.
Solution
Audits every frame, wall, and slab section against its assigned name. Exports a report isolating mismatches with named and actual dimensions side by side.
Impact
Processes 1,000+ sections in under 30 seconds. Caught two frame mismatches that had passed visual review.
How it works

Section names carry the intent — dimensions, grade, sometimes a type prefix. The tool parses that intent out of the name, reads the actual geometric properties through the API, and compares the two.

Names that cannot be parsed are reported separately rather than silently passed, because a section the checker cannot read is exactly the one worth a human look. Output is an Excel workbook split by element type with a dedicated mismatches sheet.

Excel to AutoCAD Beam Schedule

PythonAutoCAD automationExcel
Problem
Beam schedules are transcribed from design output into drawings by hand. Every revision reopens the same error surface.
Solution
Reads a reinforcement schedule from Excel and draws dimensioned beam elevations directly in AutoCAD, with rebar callouts, hooks, beam marks, layers, and annotation applied automatically.
Impact
Output cross-checked against manually produced schedules for the same beams.
How it works

The schedule is parsed into beam objects — span, section, top and bottom reinforcement, stirrup spacing — then each is drawn as an elevation with reinforcement lines, hook geometry, and callouts placed relative to the beam extents rather than at fixed offsets.

Drawing conventions are parameters, not hard-coded values: cover, bar gap, hook offsets, and dimension positioning are all exposed so the output matches an office standard rather than mine.

Rice Husk Ash Strength Predictor

PythonNeural networkM.Tech thesis
Problem
No code-based method predicts compressive strength for rice husk ash mixes, so proportioning them means casting samples and waiting 28 days.
Solution
A neural network predicting 28-day compressive strength from six mix-proportion inputs: rice husk ash, cement, water, fine and coarse aggregate, and superplasticiser.
Impact
[metric] of [value] against experimental results.
How it works

Rice husk ash is a pozzolanic replacement for cement, and its strength contribution is not linear in the replacement ratio — which is why IS 456 has nothing to say about it, and why a fitted model earns its place here.

The network takes the six mix quantities directly, with the trained model loaded at runtime so a mix can be re-proportioned and re-predicted in seconds. The interface keeps a prediction history so successive trials can be compared.
